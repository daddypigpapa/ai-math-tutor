# 검증 체크리스트 (구현명세 12절 기준)

**전체 미검증.** 아래 항목은 모두 아직 실행해 본 적이 없다. 위에서부터 순서대로 하고, 앞 단계가 막히면 뒤로 가지 않는다.
명령은 프로젝트 폴더에서 Windows PowerShell 5.1 기준.

## 0. 환경
```powershell
python -m venv .venv ; .\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```
기대: 전부 통과. `tests/` 는 API 키·`~/claude/key.env` 를 쓰지 않도록 막아 두었다(`conftest.py`).

## 1. 자료 생성·검증 (verify.py, generate.py)
- [ ] `python -m pipeline.seed` → "시작 문제 12개 중 verified 12개". (한 개라도 draft 면 이슈 코드가 출력된다 — 시작 문제의 손으로 쓴 오답 식을 의심)
- [ ] `tests/test_verify.py`: 일부러 틀린 단계/오답이 이슈 코드(`step_value_mismatch`, `answer_mismatch`, `distractor_equals_answer`, `distractor_duplicate`, `wrong_count`, `error_type_duplicate`, `sympy_parse_error`, `error_type_not_applicable`, `error_type_mismatch`)로 걸러지는가.
- [ ] 덜 인수분해한 오답 `2(x^2 - 4)` 가 정답 `2(x - 2)(x + 2)` 와 구분되는가(`test_factored_incomplete_is_distinct_from_answer`).
- [ ] **실 API(키 필요)**: `python -m tests.eval.run_eval --judge` → `generation_pass_ok` (재시도 2회 안에 95%), `plausibility_ok`(4점 이상 90%). 미달이면 명세 12절대로 프롬프트·예시·실수유형 사전을 먼저 고치고, 그래도 안 되면 생성을 두 번 호출로 분리. 채점기를 바꿀 때는 먼저 `--rejudge <결과폴더> --judge-prompt <새 프롬프트>` 로 같은 출력을 다시 채점해 알려진 오판이 고쳐지는지 확인한다.
- [ ] **실 API 요청 형식 확인** `app/llm.py`: Claude `output_config.format`(json_schema)·`effort`, Gemini `generationConfig`. 응답 거절(400)이 나면 필드 이름부터 의심. 모델 이름은 `config.toml`.

## 2. 학습 화면 (learn.py, web/learn.html)
- [ ] `tests/test_learn.py`: 점수 10/5/0, 계산단계 본 뒤 5/2/0, 힌트·출제의도 감점 없음, 선택 전 응답에 정답 정보 없음, 문제집 순서→AI 문제, 이어 풀기.
- [ ] **브라우저(실제 화면)**: `.\scripts\run_server.ps1` → `http://localhost:8000` → 이름 선택 → 10문제 끝까지. 수식이 KaTeX로 그려지는지, a/b/c/d 흐름, 오답→코칭→"다시 풀어볼게"→3지선다, 2번 틀림→계산단계 전체 표시, 진행 막대, "다음 문제".
- [ ] 개발자도구 Network 탭에서 `/api/attempts/*/choices` 응답에 정답 표시가 없는지.
- [ ] 아이 PC에서 `http://<서버 IP>:8000` 접속(방화벽 규칙 적용 후).

## 3. 실시간 코칭 (coach.py)
- [ ] `tests/test_coach.py`: 누설 변형 탐지, 200자·반말·마크다운 검사, 키 없이 저장된 피드백으로 진행, 한도 초과 시 저장 문장, 단계 설명 캐시.
- [ ] **실 API**: `python -m tests.eval.score_coaching --judge` → 누설 0%, 200자·반말 100%, 틀린 단계 짚음 90%.
- [ ] `.env` 의 `GEMINI_API_KEY` 를 지운 상태로 서버를 띄워 오답을 골라도 저장된 피드백이 나오는지(수동).

## 4. 분석·약점 복습 (stats.py)
- [ ] `tests/test_stats.py`: 10문제 중 5개 정답 → 약점 판정 → 복습 문제 10개 생성(가짜 LLM) → 버튼 표시, 계산단계 본 정답이 오답 집계, 복습 후 자동 해제.
- [ ] 실 API로 복습 문제 10개가 실제로 verified 되는지: 서버에서 10문제 중 5개 정답 → 부모 화면 "문제 관리"의 `ai_review` 행 확인.

## 5. 부모 화면·보고서 (parent.py, report.py)
- [ ] `tests/test_report_api.py`: 화면 숫자 = DB 조회, 보고서 숫자 = 계산값, LLM이 숫자를 바꾸면 정해진 문장으로 대체, PIN 없이 401/503.
- [ ] 브라우저 `/parent`: PIN 입력, 모든 메뉴(요약·단원별·실수유형별·풀이 기록·주간 보고서·검토 필요·문제 관리·AI 호출 기록·AI 비용·설정) 렌더링.
- [ ] 디스코드: `.env` 에 웹후크 설정 후 `python -m app.report --learner all` → 채널 도착, `weekly_reports.discord_sent=1`. 일부러 틀린 웹후크로 실패 기록·부모 화면 표시.
- [ ] `.\scripts\register_tasks.ps1`(관리자) → 재부팅 후 서버 자동 실행, 일요일 21시 작업 등록.

## 의심 지점 (실행 전 코드 리뷰에서 먼저 볼 곳)
1. `pipeline/verify.py` `canon()` / `norm_display()` — sympy `evaluate=False` 구조 순회와 서식 정규식. 인수분해 꼴 비교의 핵심.
2. `app/coach.py` `leaks()` — 토큰 파싱 기반 누설 탐지의 오탐(정답 못지않게 정상 코칭을 버리는 쪽)/미탐.
3. `app/llm.py` — 실 API 요청 본문(미검증). 키가 없을 때 호출 없이 실패하는 경로.
4. `app/stats.py` `refresh_weak()` / `pick_review_problems()` SQL.
5. SQLite 동시 접근: 요청별 연결 + 백그라운드 스레드의 별도 연결(`check_same_thread=False`, WAL).
6. `web/app.js`·`web/parent.js` — 브라우저에서 한 번도 열어 보지 않았다.
