## 검증 중 발견해 고친 버그
1. **홈 화면에 `null` 글자 표시** (`web/app.js` `show()`가 null 을 그대로 붙임).
2. **TLS 인증서 오류**: 이 PC는 보안 프로그램 때문에 `self-signed certificate` 오류로 모든 API 호출이 실패 → Windows 인증서 저장소를 쓰도록 `truststore` 적용.
3. **누설 검사 오탐지**: `2x`, `(x−5)(x+3)` 처럼 곱셈 기호 없는 표기를 파싱하지 못해 항 순서가 바뀐 정답 누설을 놓침 → 암묵적 곱셈 파싱 추가.
4. **코칭이 풀이를 새게 함(실제 발생)**: 틀린 단계 앞의 계산단계(명세 8절 입력)에 정답 수(예: 7, −8)가 있어 AI가 그대로 말함 → 프롬프트 규칙 + `_step_leak` 코드 검사 추가.
5. **코칭의 틀린 단계 짚기 82~86% → 92%**: 프롬프트에 실수유형 이름·틀린 단계 번호를 넣고 "추측하지 말고 저장된 진단을 따르라" 지시.
6. 모델이 붙이는 백틱(`` ` ``)이 있으면 단계 설명 전체가 버려짐 → 백틱·별표는 지우고 사용.
7. 오답 표기 `(2x+5)(2x+5)2`(곱셈 기호 소실) → `\cdot` 로 표시.
8. 생성 오답의 실수유형 이름이 안 맞는 경우: `FACTOR_INCOMPLETE`(값이 원래 식과 같아야 함)·`FACTOR_SIGN`(각 인수 부호만 반대) 은 코드로 검사해 재요청하게 했고, 프롬프트에 유형 정의 추가(`generate_v2`).
9. 판정용 모델이 `max_tokens` 로 응답이 잘림(Gemini 사고 토큰) → `thinking_budget=0`, 한도 상향. 연결이 끊기면(느린 호출) 1회 재시도.
10. 브라우저가 옛 `app.js` 를 캐시 → 정적 파일 `Cache-Control: no-cache`.

## 5문제 종단 테스트 (중3 인수분해, `problems/m3-poly/m3-poly-f01~f05.json`)
Claude가 생성하고 sympy가 검증한 문제 5개(공통인수·완전제곱식·합차공식·x² 계수 1·x² 계수 1 아님). HTTP API로 아이 동작을 재현:

| 문제 | 시나리오 | 기대 | 결과 |
|---|---|---|---|
| f01 | 힌트·출제의도 본 뒤 첫 시도 정답 | 10점 | 10점 |
| f02 | 오답 → 코칭 → 재시도 정답 | 5점 | 5점, 틀린 보기 제외 3지선다 |
| f03 | 계산단계 본 뒤 첫 시도 정답 | 5점 | 5점 |
| f04 | 오답 2번 | 0점, 정답·단계 공개 | 0점, 공개됨 |
| f05 | 계산단계 + 단계 설명 3단계 + 오답 후 재시도 정답 | 2점 | 2점, 4번째 요청은 캐시 |

- 끝난 문제에 또 답하면 409, 문제를 다 풀면 `done`.
- 부모 화면 집계: 5문제, 점수 22, 도움 받아 맞힘 2, 정답률 20%(c를 본 정답은 오답 집계).
- AI 호출 기록에 코칭·단계 설명·평가("도움됐어") 모두 저장.
- **품질 한계**: 오답 보기 중 일부는 실수유형 이름이 어색하다(예: f02 `(4x+5)(x+5)` 를 FACTOR_COMMON 으로 표시). 위 생성-2 미달과 같은 문제다.

## 생성-2 타당성 개선 (2026-10-25, PC-서재, Python 3.14.6)

평가 세트 36문제(채점 대상 34개 × 오답 3개 = 102건), 채점기 `judge_generate_v1`(Gemini 2.5 Flash). 판정 실패 0건(실패 호출도 분모에 넣도록 고침).

| 실행 | 생성기 | 생성-1 | 생성-2 (4점 이상) | 결과 폴더 |
|---|---|---|---|---|
| 기준선 | `generate_v2` | 34/34 | **75.5%** (77/102) | `20261025-173606` |
| 1차 개선 | `generate_v3` + 적용 가능 유형 제한 | 34/34 | **88.2%** (90/102) | `20261025-175622` |
| 2차 개선 | + `FACTOR_PAIR` 검사, `MULT_CALC` 정의 축소 | 34/34 | **87.3%** (89/102) | `20261025-180604` |

결과 폴더는 `tests/eval/results/` 아래(깃 제외, PC-서재에만 있음). 1차와 2차의 차이(1건)는 실행 간 변동 범위다.

**원인 (기준선 탈락 25건 분류):** 오답 3개를 서로 다른 유형으로 채워야 하는데, 문제에 맞는 유형이 3개가 안 되면 엉뚱한 이름을 붙였다. 공통인수가 없는 `x²+7x+12`에 `FACTOR_COMMON`을 붙이거나, 인수분해 문제에 `COEF_COMBINE`을 붙이는 식이다. 유형별 탈락: `FACTOR_COMMON` 9/12, `COEF_COMBINE` 6/17. 코드로 검사하던 유형은 적었다: `FACTOR_SIGN` 0/9, `FACTOR_INCOMPLETE` 2/10.

**바꾼 것:**
1. `verify.applicable_error_types` — 식의 구조(분배 후 동류항 유무, 이항식 제곱, 합차 쌍, 공통인수, 인수 개수, 삼항식)로 고를 수 있는 유형을 정한다. 생성 스키마의 `enum`과 사용자 메시지(`<allowed_error_types>`)를 이 목록으로 좁히고, 검증에서 벗어나면 `error_type_not_applicable` 로 재요청한다.
2. 유형 2개 추가(명세 4절과 다름 — README 가정 12): `MULT_CALC`(곱셈·제곱·제곱근 계산 실수), `FACTOR_PAIR`(곱·합 중 한 조건만 맞는 두 수). 단순 삼항식 인수분해와 `−2x(x−4)` 같은 식은 기존 유형으로는 맞는 유형이 2개뿐이었다. `FACTOR_PAIR` 는 원래 식과 계수가 정확히 하나만 다른지 코드로 검사한다.
3. 유형 정의를 `taxonomy.DEFINITIONS` 한 곳으로 옮기고 생성 프롬프트(`generate_v3`)가 읽는다.
4. 시작 문제 5개(s03·s07·s08·s11·s12)의 잘못된 이름표를 바로잡았다(예: s07 "계수를 곱할 때 더함" `COEF_COMBINE` → `MULT_CALC`).

**시도했지만 채택하지 않은 것 (실측 근거):**
- 채점기에 정답·유형 정의·맞는 단계를 더 준 v2: 같은 기준선 출력 재채점에서 75.5% → 62.7%. 더 엄격해졌을 뿐 v1 오판 5건 중 1건만 고쳤고, 정의 그대로인 오답에 새로 1점을 줬다. 같은 v1 로 재채점하면 75.5% 그대로(흔들림 작음).
- 코드 규칙 후보 4개("인수분해 오답은 곱의 꼴", "맞는 단계보다 항이 많으면 탈락", "인수분해 `SIGN` 은 인수 하나만 부호 반대", "인수분해 `SQUARE_FORMULA` 는 제곱 꼴 유지"): 기존 오답 306건에 대 보니 4~5점 오답도 많이 걸러 내서 버렸다.

**남은 탈락 13건 (2차 개선):**
- 채점기 오판으로 보이는 4건. 실행마다 되풀이된다. ① e0017 `(x+4)(x+5)` — `FACTOR_SIGN` 정의 그대로인데 "부호 하나만 바꾼 게 아니다"라며 1점. ② e0102 `x²−2√2x+2` — `DIFF_SQUARES` 정의 그대로인데 1점. ③ e0103 `x²/4+6x+9` 를 "정답"이라 판정(정답은 `3x`). ④ e0019 `(x−3)(2x−1)` 의 상수항을 −1로 잘못 계산.
- 생성기 몫 약 9건: 3점대 애매한 오답(빠뜨린 항 위치가 어색함 등), 세제곱 공식 문제(e0011·e0012)의 `COEF_COMBINE`(여러 실행에서 1~2점), 다른 유형 이름으로 낸 같은 오답(e0024 `(2x−3)(2x+3)` 을 `SQUARE_FORMULA` 로).
- 채점기 오판 4건을 빼면 89/98 = 90.8% 이지만, 이것은 에이전트의 분류이며 기준 판정은 아니다.

**기존 AI 문제 f01~f05:** 새 규칙으로 보면 5문제 모두 이름표가 맞지 않는 오답이 있다(합계 7개, 예: f03 `25x²−49` 의 `FACTOR_COMMON`). 다시 생성하지 않았다.

테스트: `pytest` 97개 통과(적용 가능 유형 7개 사례, 적용 불가 검출, `FACTOR_PAIR` 검사 추가).
